## Blue Team Flag — X-Forwarded-For

The access log entry at **18:49:30** contains an unusual `X-Forwarded-For` value:

```
X-Forwarded-For: UEhBTlRPTUdSSUR7QkxVRV9MMGdfSHVudDNyX000c3Qzcn0=
```

Decode it:
```bash
echo "UEhBTlRPTUdSSUR7QkxVRV9MMGdfSHVudDNyX000c3Qzcn0=" | base64 -d
```

Result: **`SCENARIO75{BLUE_L0G_HUnt3r_M4st3r}`**

This value is embedded as the Blue Team flag to reward careful log analysis.

## Key Anomaly Signatures

### WAF Block then Bypass Sequence

A WAF block followed quickly by a successful request to the same endpoint is a strong indicator of WAF evasion. Look for:
- `403` on `/api/feedback` (18:50:15)
- `200` on `/api/feedback` shortly after (18:51:10)

### Cookie Replay

An `adm_sess` cookie presented without a preceding `/api/verify-mfa` call from the same IP is a session replay indicator.

Error log signature:
```
[CRITICAL] Cookie replay detected: adm_sess reused from 10.10.14.50
```

### Authentication Bypass Anomaly

```
[CRITICAL] Authentication bypass anomaly: session replayed at 10.10.14.50
```

This event at 18:53:10 indicates the simulated attacker successfully accessed the dashboard without following the normal authentication flow.

## Application Security Headers

Inspect the `X-Powered-By` header:
```bash
curl -I http://127.0.0.1:3075/
# X-Powered-By: SCENARIO75{Node.js}
```

This is the intentional CTF header — the normal Express header has been replaced.
